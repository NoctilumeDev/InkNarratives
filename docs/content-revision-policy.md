# 正文修订时间契约

“正文修订”回答的是一个窄而明确的问题：**读者正在阅读的文学、传记或叙事正文，最后一次发生实质变化是什么时候？**

它不是文件或代码修改时间，也不是 CSS、JavaScript、交互状态、校验器或部署流水线的更新时间。

## 计时范围

每件作品以其 HTML 中第一个 `<main>` 元素的可读文本为默认正文边界。阅读界面位于 `<main>` 之外时，可以在额外的 `<article>` 上标记 `data-content-revision-scope`，将那一段可读文本纳入同一份正文指纹。夜航船的三篇阅读正文因此以隐藏的静态 `<article>` 作为唯一内容源，运行时只把同一份节点内容放入阅读弹层。未标记的弹层、页脚和装饰区不自动扩张正文边界。

校验器会：

1. 在仓库受控的静态 HTML 子集内，按注释、引号属性、真实标签和 raw-text 边界识别结构，再移除注释以及真实的 `style`、`script`、`template`、`svg` 元素；
2. 去除其余 HTML 标签并解码字符实体；
3. 将连续空白折叠为单个空格；
4. 对所得 UTF-8 文本计算 SHA-256。

作品正文以外如果声明“正文修订”日期，应使用 `<time data-content-revised datetime="YYYY-MM-DD">YYYY-MM-DD</time>`。清单用 `declaredRevisionMarkers` 声明每篇独立作品预期的标记数量；静态校验器会核对数量，并把机器日期、标签文本与清单日期逐项比对。展厅展签的机器日期与点分格式标签文本也会同时核对。

该扫描不是通用 HTML5 解析器。静态校验只能证明当前仓库允许的源文件结构与声明一致，不能证明浏览器错误恢复后的任意畸形标记，也不能证明元素在最终 CSS 和浏览器状态下实际可见。日期的真实展示仍属于带日期的浏览器基线与人工复验范围。

以下变化需要更新 `content-revised` 日期和 `docs/content-revisions.json` 中的指纹：

- 增删或改写标题、段落、引文、注释、图注等正文；
- 改变作品内部的标题、标签文案或章节顺序，并由此改变文学或叙事含义；
- 修正事实、人物、时间、出处或文字讹误。

以下变化不推进正文修订日期：

- CSS、动画、响应式布局和纯视觉资源调整；
- JavaScript 交互实现、性能优化和兼容性修复；
- 作品可用状态、交互提示和校验边界说明等编辑界面文案；
- URL、部署、CI、重定向与仓库文档变化；
- 不改变可读文本的语义标签或无障碍结构修复。

## 更新流程

指纹变化只能证明校验范围内的可读文本不同，不能替代文学语义判断。维护者应先判断变化是否改写了作品正文。

正文发生实质变化时，应在同一个提交中完成三件事：

1. 更新作品 `<head>` 中的 `<meta name="content-revised">`；
2. 更新展厅展签中的 `<time datetime>`；
3. 更新 `docs/content-revisions.json` 的日期与文本指纹。

如果变化只涉及作品可用状态、交互提示或校验边界，文学正文没有改写，则保留原日期，只更新指纹，并在提交说明或基线文档中记录原因。

`node scripts/verify-repository.mjs` 会核对元数据、展签、清单和指纹的一致性，并在文字漂移时要求人工裁决；它不会自行把代码或界面修改解释成文学内容修订。
